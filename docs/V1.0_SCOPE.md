# A-market V1.0 范围

## 1. 版本目标

V1.0 建立一条可独立运行、可追溯、可检查的 A 股行情数据主链：从外部行情事实进入
ClickHouse，形成分钟级个股、全市场和板块结果，并提供本机只读查询能力。

项目配置中的当前版本号为 `1.0.0`。本文描述的是仓库中的版本边界，不证明实时服务状态。

## 2. 纳入范围

### 盘中数据

- 交易日固定 254 节点计划。
- 全 A 快照。
- 涨停池、跌停池和炸板池。
- 板块指数快照。
- 个股一分钟派生。
- 全市场状态。
- 概念、行业和风格板块状态。

### 日级数据

- 交易日历缓存。
- 原始日线。
- 复权事件。
- 前复权日线结果。
- 日线任务状态。

### 板块基础数据

- 板块目录。
- 带起止日期的板块成员历史。
- 板块映射同步状态。

### 运行和查询

- ClickHouse 本地容器定义。
- 采集器常驻运行脚本。
- 日线和板块映射计划任务脚本。
- 命令行状态检查。
- 本机 AI 状态查询和受限制的 ClickHouse 只读查询。
- 基础测试，覆盖时间计划、派生、接口批量和异常恢复等关键行为。

## 3. 部分完成

| 项目 | 当前完成部分 | 尚缺部分 |
|---|---|---|
| 飞书机器人 | 长连接接收、日志、`/A` 指令识别、自启脚本 | 查询路由、权限规则、结果组织和消息回复 |
| 外部查询接入 | 本机只读入口和标准输入输出入口 | 面向业务方的稳定公开接口和版本约定 |
| 运维说明 | 安装、启动、状态脚本已存在 | 完整故障手册、告警闭环和恢复目标 |

## 4. 不纳入 V1.0

- 自动交易或券商账户操作。
- 交易策略执行、收益承诺或个性化投资建议。
- 公网数据库访问。
- 面向用户的完整网页、桌面或移动客户端。
- 自动修改数据的 AI 工具。
- 未经审核的历史补采、批量重算或表结构迁移。
- 使用未来信息修补过去时点的行情和涨跌停状态。

## 5. V1.0 验收口径

以下条件需要通过实际环境检查后才能判定“运行验收完成”：

1. ClickHouse 可连接，`market` 数据库所需表存在。
2. 交易日能生成严格对应的 254 个计划编号。
3. 成功节点能保存原始事实，并形成对应个股和市场派生结果。
4. 板块映射完整时，成功节点能形成板块指数事实和三类板块状态。
5. 失败节点保留失败状态，不生成伪造行情，也不影响后续节点编号。
6. 日线流程能按交易日历执行并记录状态。
7. 只读查询入口拒绝写入类语句，并执行行数和超时限制。
8. 密钥不出现在仓库和普通日志中。
9. 自动任务是否安装、是否在运行、最近一次是否成功均能单独核对。

## 6. 变更规则

- 新能力先更新本文的范围和状态，再进入实现。
- 数据口径变化需同步更新对应派生文档。
- 表结构变化需同步更新 `sql/hithink_snapshot.sql` 和数据库文档。
- 查询入口变化需同步更新接口文档。
- “脚本已存在”“任务已安装”“任务正在运行”是三个不同事实，报告时不得混为一谈。
