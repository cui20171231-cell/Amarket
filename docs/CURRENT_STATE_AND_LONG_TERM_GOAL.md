## 3. 当前正式运行链路

```text
开机后主服务常驻
        ↓
08:50 确认当日是否交易日
        ├─ 非交易日：板块映射、254节点、日K和复权事件全部跳过并记录原因
        └─ 交易日：
             ↓
          本地计算并强制保证完整254节点计划
             ↓
          板块映射（最晚运行到09:10，失败或超时不阻断盘中采集）
             ↓
          09:15:15—15:00 按固定编号执行盘中采集、派生和聚合
             ↓
          第254号不完整时继续重试

同一主服务中的独立日线通道：
16:00 日K；周一同时刷新复权事件
失败后每10分钟重试，最晚到次日08:30
```

254 计划完全由本地固定规则生成，不从外部接口下载。所谓“强制生成”是强制保证当天存在一份
正确、完整、唯一的计划，不是每次重启覆盖执行状态：

- 0 条时一次生成 254 条。
- 少于 254 条时只补缺失节点。
- 已有 254 条时校验编号、时间和时段后继续使用。
- 出现多余节点或编号、时间不一致时明确报错，不静默覆盖。

## 4. 重启与故障恢复约定

目标行为已经固定为：

| 情况 | 系统行为 |
|---|---|
| 08:50 前正常启动 | 等待08:50，确认交易日后执行完整链路 |
| 08:50 后盘中重启 | 不补跑板块映射；校验/补齐本地计划，错过节点记为跳过，继续后续节点 |
| 15:00 后重启 | 第254号未成功则继续补；已经成功则不重复采集 |
| 16:00 后重启 | 检查当日日K，未成功则补跑，成功则不重复执行 |
| 次日08:30前重启 | 检查前一日未完成的日K并在截止时间内补跑 |
| 数据库暂时未就绪 | 主服务持续等待并重试，不把数据库故障误判为非交易日 |
| 交易日接口未知且无当日缓存 | 每5分钟重试，不猜测交易日、不启动采集 |
| 普通盘中接口失败 | 保存实际成功部分并记录失败；下一固定节点继续执行 |
| 第254号关键输入失败 | 持续重试第254号，但不阻塞独立的16:00日K通道 |

2026-08-31 曾出现过两类实际摩擦：启动阶段的数据库结构语句解析错误，以及收盘后重启触发不应
补跑的板块映射。前者已经修复并通过多次启动验证；后者在新版本重启现场已经确认会跳过映射。

## 5. 已有自动检查点

主服务在以下时间检查关键状态，并在异常时写入 `CHECKPOINT_ALERT`：

- 08:55：交易日确认。
- 09:00：每日任务状态计划。
- 09:10：完整254节点计划。
- 09:16：第一号节点是否已经结束。
- 15:05：第254号是否成功。
- 16:05：日K是否开始或成功。
- 16:30：日K是否成功。

这些检查目前能够留下明确日志，但“写日志”不等于“用户已经收到通知”。

## 6. 长期目标

长期目标不是偶尔成功运行，而是在不持续占用用户精力的情况下稳定运行一至两年：

- 机器可以随时断电、重启或短时离线。
- 恢复后自动判断当前所处阶段并继续工作。
- 只允许缺失断电期间无法采集的分钟节点，不因恢复流程造成重复编号、错位或覆盖。
- 板块映射、派生或聚合故障不能无声拖死核心行情采集。
- 盘中节点、第254号、日K和复权事件各自具有清楚的恢复边界。
- 所有无法自动恢复的问题都能主动通知，而不是等用户偶然查看日志。
- 日志、磁盘、数据库、系统时间、接口额度和密钥能够长期维护。
- 每天自动给出简短、可信的运行结果，正常时无需人工介入。

## 7. 尚未完成的长期建设项

按优先级仍需完成：

1. 用下一真实交易日完成08:50至16:30的全链路现场验收，并保存验收结果。
2. 把 `CHECKPOINT_ALERT` 接入主动通知渠道；至少包含发生时间、受影响任务、是否仍在自动恢复。
3. 增加每日收盘运行摘要：计划完整度、成功/跳过/失败节点、第254号、日K、映射和重试情况。
4. 为采集日志、数据库日志和网关日志增加自动分卷与保留期限，防止长期占满磁盘。
5. 增加磁盘空间、ClickHouse健康、Docker启动、Windows任务状态和北京时间同步检查。
6. 增加接口密钥有效性、访问额度和连续失败预警。
7. 制定数据库备份、恢复演练和历史数据校验方案。
8. 定期执行断电、盘中重启、收盘后重启、数据库延迟启动和接口故障的恢复演练。

## 8. 长期验收标准

项目达到“可长期无人值守”至少应满足：

- 连续20个交易日无需人工补任务。
- 随机盘中重启后，10分钟内恢复后续节点，且不重复已成功节点。
- 收盘后重启不运行板块映射；未完成日K能够按规则补跑。
- 每个交易日的计划要么完整254条，要么明确记录无法生成的原因并主动通知。
- 第254号和日K互不阻塞，各自状态可独立核对。
- 连续故障有主动通知，恢复后有恢复通知。
- 日志和数据库空间增长受控，备份可以实际恢复。

在达到以上标准前，项目应描述为“具备自动恢复基础并进入现场稳定性验证”，不应提前宣称已经可以
完全无人值守运行一至两年。
