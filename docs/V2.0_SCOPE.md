# A-market V2.0 范围与 V1.0 差异

## 1. 版本定位

A-market V2.0 的项目版本号为 `2.0.0`，Git 标签为 `v2.0.0`。

V1.0 由 Git 标签 `v1.0.0` 和 [V1.0范围文档](V1.0_SCOPE.md)永久保存，不删除、不覆盖、
不移动标签。V2.0 是在 V1.0 独立行情主链基础上的第二个完整版本，重点从“主链能够独立运行”
扩展到“采集、派生、聚合和重启恢复能够在一个常驻服务中持续运行并被检查”。

本文描述仓库中的版本边界。机器、数据库和外部接口的现场状态仍以实际检查为准，不能只根据标签
判断正在运行的服务一定健康。

## 2. V1.0 保存内容

V1.0 保留以下首版能力：

- 每交易日固定 254 个计划节点和永久采集编号。
- 全 A 快照、涨停池、跌停池、炸板池和板块指数事实。
- 个股一分钟派生、全市场状态以及概念、行业、风格状态。
- 板块目录、成员历史、交易日历、日K、复权事件和前复权结果。
- ClickHouse `market` 数据库和单一结构文件。
- 命令行状态、本机只读查询入口和只读标准输入输出入口。
- 密钥与仓库隔离、失败节点不伪造事实、固定编号不随失败移动等基本原则。

V1.0 的历史边界继续以 `docs/V1.0_SCOPE.md` 为准，不因发布 V2.0 而回写成新能力。

## 3. V2.0 相比 V1.0 的主要差异

| 范围 | V1.0 | V2.0 |
|---|---|---|
| 项目版本 | `1.0.0`、标签 `v1.0.0` | `2.0.0`、标签 `v2.0.0` |
| 常驻任务 | 主采集器为主，日线和板块映射保留独立计划任务脚本 | 只保留一个 `HithinkSnapshotCollector` 常驻任务；交易日确认、映射、254节点和日线统一编排 |
| 交易日确认 | 08:50确认并使用本地缓存兜底 | 增加共享确认锁；未知且无当日缓存时每5分钟重试，不猜测、不采集 |
| 254计划 | 固定时间表，已有当天记录时直接复用 | 交易日确认后由本地强制保证完整254条；缺失自动补齐，错误编号、时间或多余节点明确报错 |
| 板块映射 | 可由独立任务执行，重启边界容易重复 | 移入主服务并放在计划生成之后；最晚到09:10，失败或超时不阻断盘中采集；08:50后重启不补映射 |
| 盘中重启 | 基础续跑和固定编号 | 错过节点明确记为跳过，后续节点继续；已成功节点不重复；遗留运行状态自动关闭 |
| 第254号 | 固定15:00节点 | 关键输入失败后每分钟重试，最晚到北京时间16:00，并要求使用第254号自己的收盘事实，不允许历史回退 |
| 16:00日K | 独立任务链 | 同一主服务内使用独立连接和独立执行通道，不被第254号阻塞；失败后每分钟重试，最多15次，最晚到16:15 |
| 重启补跑 | 不统一补跑已错过的定时任务 | 16:00至16:15重启检查并补跑当日日K；16:15后不再补跑；成功任务不重复执行 |
| 原始采集韧性 | 基础接口重试 | 五类接口并行隔离、单节点时间预算、限流识别、部分成功保留和第254号专项恢复 |
| 情绪状态 | 未形成独立情绪表 | 新增每节点情绪梯队、三池一致性、来源年龄、回退状态和收盘强约束 |
| 市场变化 | 基础一分钟与市场状态 | 新增19个固定检查点的约15分钟市场变化，并记录真实基准和回退年龄 |
| 板块研究 | 三类板块状态 | 新增板块成交份额迁移、独立排名、扩散状态和19节点轨迹 |
| 核心候选 | 未形成正式候选层 | 新增核心板块和核心个股候选，保存可解释证据，不输出买卖结论 |
| 战略观察 | 未建立配置层 | 新增长期战略板块观察名单，与当天行情候选分层管理 |
| 聚合消费 | 查询基础表 | 新增19节点本地市场状态聚合包、原子落盘、完整性校验和只读包读取工具 |
| 状态检查 | 基础任务和节点状态 | 增加原始、派生、聚合分阶段状态、关键时间检查和 `CHECKPOINT_ALERT` 日志 |
| 数据结构约束 | 基础表和固定编号 | 增加节点号统一字段、阶段状态、派生表、聚合状态、来源追溯和收盘一致性约束 |
| 自动测试 | 覆盖V1主链 | 当前包含145项测试，覆盖计划完整性、交易日门、恢复、派生、聚合、状态和结构规则 |

## 4. V2.0 正式能力范围

### 4.1 本地计划与运行调度

- 08:50确认交易日。
- 交易日确认后，本地计算并校验/补齐完整254节点计划。
- 板块映射最晚运行到09:10，不允许拖死主行情采集。
- 自2026-09-02起，09:15:08至15:00按固定计划采集、派生和聚合；历史日期仍按原计划时间解释。
- 第254号持续恢复，但16:00日线使用独立通道。
- 非交易日明确跳过映射、254节点、日K和复权事件并记录原因。

### 4.2 数据事实与派生

- V1.0全部原始事实和基础派生继续保留。
- 每节点情绪梯队状态。
- 19节点市场约15分钟变化。
- 三类板块成交份额迁移与内部扩散。
- 核心板块、核心个股候选及可解释证据。
- 长期战略板块观察配置。

### 4.3 聚合与只读消费

- 19个固定节点形成市场状态聚合包。
- 聚合包在全部前置条件满足后原子写入本地文件。
- 聚合包读取工具只读取已经存在并通过校验的文件，不在读取时重算数据库。
- 本机只读查询入口继续拒绝写入类操作。

### 4.4 自动恢复与检查

- Windows开机启动、单实例锁和异常退出自动重启。
- 数据库未就绪时持续等待。
- 盘中重启跳过关机期间的节点并继续后续时间点。
- 16:00日K失败后每分钟重试，最多15次，并支持16:15前重启补跑。
- 08:55、09:00、09:10、09:16、15:05、16:05、16:20关键状态检查。
- 运行状态能够区分成功、部分成功、失败、阻断、超时、运行中和跳过。

## 5. V2.0 不改变的边界

- 不包含自动交易、券商账户、下单或持仓管理。
- 不输出收益承诺、个性化投资建议或未经证据支持的主线、龙头判断。
- 不开放公网数据库写入。
- 不允许AI工具修改行情事实、任务状态或数据库结构。
- 不用盘后最终结果伪造盘中历史，不补造断电期间无法获得的分钟事实。
- 不把“代码存在”“任务已安装”“任务正在运行”“当天运行成功”混为同一事实。

## 6. 项目版本与数据模型版本的区别

以下名称不能随着项目升到2.0而机械改名：

- `candidate_model_version = 'V1'` 表示核心候选公式版本，目前仍是候选模型V1。
- 聚合包中的 `package_version = 'V2'` 表示聚合包结构版本，恰好也是V2，但它与Git项目标签
  不是同一个版本体系。
- `docs/hithink_core_candidates_v1_v2.md` 中的V1/V2表示候选公式现状和未来升级边界。

项目版本 `2.0.0` 只表示本次整个仓库的发布版本，不篡改上述独立数据口径。
