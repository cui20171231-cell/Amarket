# 市场状态恢复聚合数据包

这个数据包是第7个临时聚合层，不是第7张数据库表。MCP只提供一个薄读取工具
`get_market_state_package`，直接定位、校验并原样返回已有JSON，不在读取时重新聚合。
生成器只读查询前6张业务表和战略观察配置，完成拼装、排序及确定性比较，不写数据库。
自动执行由独立的 `app/hithink/aggregation.py` 聚合模块负责；打包不属于派生模块，也不发送外部通知。

## 生成方式

```powershell
python -m app.market_state_package --trade-date 2026-08-28 --target-time 10:30
```

## 自动生成与通知

交易日内只有以下19个固定节点生成数据包：

```text
09:25 09:30 09:45 10:00 10:15 10:30 10:45 11:00 11:15 11:30
13:00 13:15 13:30 13:45 14:00 14:15 14:30 14:45 15:00
```

自动顺序固定为：原有个股/市场/三类板块状态 → 情绪状态 → 15分钟市场变化 →
板块成交份额迁移 → 核心板块候选 → 核心个股候选 → 本地聚合包。
战略观察表是长期配置，打包时读取，不做每日派生。

数据包先完整写入临时文件，再一次性替换正式文件：

```text
data/market_state_packages/YYYYMMDD/YYYYMMDDnnn.json
```

正式文件生成后保留在本地，供只读工具按交易日期、节点时间或节点编号读取。
聚合模块不再向CCChat或其他外部服务发送就绪通知。

不传交易日期时使用 `hithink_market_delta_15m` 最近可用交易日。目标时间支持 `HH:MM` 或
`HH:MM:SS`，生成器在当天19个固定检查点中选择距离最近的真实节点，同时返回请求时间、
实际节点时间和距离秒数，不把10:30:15伪装成严格10:30:00。

默认使用当前有效战略观察名单回看目标日期。需要严格恢复历史当时名单时增加：

```powershell
--historical-watchlist
```

此时按 `effective_from/effective_to` 读取。

## MCP读取

当用户输入 `/ai 10:15` 或要求恢复指定盘中节点时，优先调用：

```text
get_market_state_package(target_time="10:15")
```

也可以按节点读取，例如 `node_seq=178`。日期不传时，从数据包根目录向前寻找最近一个包含
有效JSON的日期目录。读取器只接受结构化日期、时间和节点号，不接受用户传入的文件路径。
没有精确节点时返回前后可用节点，不自动替换成邻近包。

### 等待目标包就绪

自动准点复盘只启动一次工具调用，并在调用内部等待：

```text
10:30、11:30、14:00：wait_for_ready=true, retry_interval_seconds=10, max_wait_seconds=120
15:00 / 254：wait_for_ready=true, retry_interval_seconds=10, max_wait_seconds=300
```

工具只轮询目标正式`.json`文件；聚合模块仍采用“先写临时文件、完成后原子替换正式文件”的方式，
读取器不会读取`.tmp`。正式文件出现后必须能完整解析，并且交易日、采集编号、节点号和计划时间
全部一致才返回`OK`。等待超时不会退回上一节点，不会查询ClickHouse，也不会触发重新聚合。

## 时间比较规则

15分钟变化直接读取已经固化的 `hithink_market_delta_15m`。30/45/60分钟变化查询时临时从
`hithink_market_state` 计算：在同一连续交易时段内，寻找不晚于目标检查点减去指定分钟数的
最近有效市场状态。禁止跨午休、跨交易日，也不使用节点编号相减推算分钟。

如果目标状态发生回退，数据包同时返回当前实际来源时间、来源年龄、基准时间和实际跨度秒数。
因此请求30分钟但当前源回退1分钟时，实际跨度可能是1740秒，不能解释成严格1800秒。

## 核心板块结构轨迹

核心板块只对概念和行业临时组织两套轨迹，不新增数据库表：

- `trajectory_recent_5_nodes`：来自概念/行业状态表最近5个有效原始节点，用于观察最近几分钟变化。
- `trajectory_15m_last_5`：来自最近5个固定目标节点，用于观察中短周期持续性。

两套轨迹都返回价格、广度、累计和即时成交份额、涨停/炸板、新高/新低以及数据来源状态。
原始节点没有候选计算，因此其 `candidate_rank`、`candidate_score_v1` 固定为NULL。15分钟关键节点
如果当时没有进入候选，这两个字段同样为NULL，禁止从前后节点补排名或分数。轨迹保持真实NULL，
保留FALLBACK来源时间和年龄，下午从13:00重新开始，不跨午休。

战略观察排名轨迹仍来自 `hithink_sector_capital_migration` 的完整同类成交份额排名，所以战略板块
即使没有进入候选也保留轨迹。

## V2日内演化路径

V2不新增数据库表，只在生成JSON时按既有19个固定节点临时组织全天路径。时间轴固定为：

```text
09:25 09:30 09:45 10:00 10:15 10:30 10:45 11:00 11:15 11:30
13:00 13:15 13:30 13:45 14:00 14:15 14:30 14:45 15:00
```

`market.intraday_trajectory` 通过每个目标节点的真实市场状态来源恢复市场广度、涨跌强度、量能、
新高新低和一分钟价格表达。10:30包只返回截至10:30的6个节点，15:00包返回19个节点，
禁止包含未来数据。13:00保留为下午基线，路径可以同时展示上午和下午，但不把午休解释成连续变化。

`emotion.intraday_trajectory` 使用同一组固定节点，返回从09:25到当前包的情绪路径。每个节点只保留
计划时间以及涨停、跌停、炸板、封板率、连板梯队、晋级率和高位板等19个业务字段，不返回采集编号、
来源编号、来源时间、回退标识或来源年龄。当前节点的数据质量仍统一记录在顶层 `data_quality` 中。

`core_sector_intraday.trajectories` 只取当前包实际入选的核心概念和核心行业，不再纳入历史退出板块、
资金迁移异常板块或战略观察并集。每个板块保存从09:25到当前包的固定节点事实路径；候选排名和
候选分数只在当时实际进入候选时存在，否则保持NULL。所有FALLBACK节点保留目标时间、实际来源
时间和来源年龄。

## 结论边界

数据包只返回事实、排名、差值、来源时间、持续性和确定性交叉关系。它不会生成“主线”“龙头”
“强化”“退潮”“买点”或“卖点”等判断。
