# A-market 接口草案

## 1. 定位

本文记录仓库当前已经存在的程序入口和它们的权限边界。A-market 目前没有面向公网的业务接口；
已有网络查询入口只绑定本机，并且只允许读取。

## 2. 本机 AI 查询入口

入口程序：`app/ai_gateway.py`

```text
地址：http://127.0.0.1:2091/mcp
端口环境变量：AMARKET_AI_GATEWAY_PORT
传输方式：流式 HTTP
权限：只读
```

端口可以通过环境变量调整。地址、依赖和启动脚本存在不表示该入口当前正在运行。

### 工具：`collection_status_query`

用途：返回 ClickHouse、盘中采集、派生、日线、板块映射和自动任务的综合状态。

输入：无。

输出：结构化状态结果，并带适合阅读的说明文本。

影响：只查询，不启动、停止、重启或修改任务。

### 工具：`get_market_state_package`

中文用途：读取市场状态聚合包。

工具从固定目录 `D:\Amarket\data\market_state_packages` 定位已经生成的JSON包，校验目录日期、
文件名、交易日、节点号、采集编号和计划时间后，原样返回完整包内容。它不查询ClickHouse、
不重新计算、不写文件，也不生成市场结论。

| 参数 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `target_time` | 文本或空 | 与节点号至少一个 | `HH:MM`或`HH:MM:SS` |
| `node_seq` | 整数或空 | 与时间至少一个 | 1至254，实际只命中已有19节点包 |
| `trade_date` | 文本或空 | 否 | `YYYY-MM-DD`或`YYYYMMDD`；不传时读取最近有效目录 |
| `wait_for_ready` | 布尔值 | 否 | 默认false；true时在一次调用内等待正式JSON就绪 |
| `retry_interval_seconds` | 整数 | 否 | 默认10，允许5至30秒 |
| `max_wait_seconds` | 整数 | 否 | 默认120，允许1至300秒；15:00任务使用300 |

`/ai 时间`、`/AI 时间`、指定盘中时间或恢复盘中状态时优先调用本工具，不先绕到自由SQL。

等待模式只轮询目标正式`.json`文件，不读取临时文件，不访问ClickHouse，不生成聚合包，也不重新
触发定时任务。文件出现后仍须通过完整JSON及身份校验。等待期内文件为空或尚未写完整会继续重试；
超时仍不存在返回`TIMEOUT`，始终损坏返回`INVALID_PACKAGE`。返回同时包含`wait_elapsed_ms`和
`retry_count`。等待模式未指定日期时固定等待上海时区当天目录，避免静默读取上一交易日同一时间；
普通手动读取未指定日期时仍使用最近有效交易日目录。

### 工具：`query_market_data`

用途：对 `market` 数据库执行受限制的只读查询。

| 参数 | 类型 | 必填 | 默认值 | 限制 |
|---|---|---:|---:|---|
| `sql` | 文本 | 是 | 无 | 首个有效关键字只能是允许的只读类型 |
| `parameters` | 键值对象 | 否 | 空 | 用于参数化查询 |
| `max_rows` | 整数 | 否 | 2000 | 1 至 10000 |
| `timeout_seconds` | 整数 | 否 | 30 | 1 至 120 秒 |

允许的开头：

```text
SELECT, WITH, SHOW, DESCRIBE, DESC, EXPLAIN, EXISTS
```

输出主要包含：数据库位置、列名、数据行、返回行数、是否截断、耗时和只读模式标记。

安全限制：数据库连接同时设置只读、最大执行时间和最大结果行数。此入口不提供插入、更新、
删除、建表、改表、启动任务或重算能力。

### 工具：`get_market_context_state`

用途：在市场状态聚合包之外，按需补充单只股票、少量股票或单个板块的盘中上下文。
查询直接复用现有分钟派生行情、板块成员映射、板块状态和涨跌停/炸板数据，数据库端完成排名和
筛选，不返回完整板块成员分钟明细。

| 参数 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `target_type` | 文本 | 是 | `stock`、`stocks`或`sector` |
| `target_time` | 文本 | 是 | `HH:MM`或`HH:MM:SS` |
| `ticker` | 文本 | 单股模式 | 6位股票代码或带交易所后缀代码 |
| `tickers` | 文本数组 | 多股模式 | 2至5只股票 |
| `sector_id` | 文本 | 板块模式二选一 | 板块代码 |
| `sector_name` | 文本 | 板块模式二选一 | 板块名称，支持忽略空格和括号匹配 |
| `trade_date` | 文本或空 | 否 | 不传时优先与最近有效市场聚合包交易日一致 |

`stock`返回个股当前状态、压缩轨迹、最多5个主要交易方向、板块内排名和少量参照股。方向筛选会
保留一个行业位置，并综合现有战略方向优先级、盘中共同运动、个股成交角色、板块市场表达和当前
相对贴合度；返回0至100分总分、每项权重、原始分、加权分和前三个未入选备选方向，便于审计。
`stocks`一次支持2至5只股票，分别返回各自上下文，不把不同方向强行合并比较。
`sector`返回板块状态、涨幅分布、成交集中度、压缩轨迹及每类最多5只关键成员。

所有成交指标只表示成交承载、关注度和份额，不表示真实净资金流入或流出。

15分钟比较按同一上午或下午内最接近“目标时间减15分钟”和“目标时间减30分钟”的有效节点取值，
允许计划节点存在15秒偏移，但不跨午休。11:30和15:00等节点因此仍能稳定返回比较值。

## 3. 本地标准输入输出入口

入口程序：`app/clickhouse_plugin_server.py`

它通过逐行 JSON 消息提供与上面相同的四个工具：

- `collection_status_query`
- `get_market_state_package`
- `get_market_context_state`
- `execute_clickhouse_readonly_sql`

该入口供本地工具集成，不是 HTTP 服务。它同样只读，参数范围与本机 AI 查询入口一致。

## 4. 命令行入口

安装项目后，命令名为：

```text
hithink-snapshot
```

当前子命令按影响分组如下。

### 查询类

| 命令 | 作用 |
|---|---|
| `status` | 查看本地服务和采集进度 |
| `sector-membership` | 查询某证券在指定日期有效的板块归属 |
| `concurrent-api-test` | 对外部行情接口做并发读取测试，不写行情数据 |

### 初始化和常驻采集

| 命令 | 作用 |
|---|---|
| `init-db` | 初始化数据库结构 |
| `run` | 生成指定交易日计划并执行采集 |
| `serve` | 常驻运行，按交易日计划采集 |
| `daily-auto` | 执行日线自动流程的当前时间段任务 |
| `sector-sync` | 同步概念、行业和风格板块映射 |

### 明确的数据变更类

| 命令 | 作用 |
|---|---|
| `market-state-backfill` | 根据已有节点补算市场状态 |
| `rederive-existing` | 根据已有原始快照重建派生结果 |
| `migrate-collection-ids` | 为历史数据补齐固定采集编号 |
| `closing-baseline` | 生成当前交易日的收盘基线 |
| `raw-all-a-closing-snapshot` | 写入当前交易日 15:00 全 A 原始快照 |
| `raw-sector-closing-snapshot` | 写入当前交易日 15:00 板块指数事实 |
| `raw-limit-pools-closing-snapshot` | 写入当前交易日 15:00 三类池事实 |

数据变更类命令不得仅因“文档里有这个命令”就执行，仍需用户明确授权。

## 5. 飞书消息入口

入口程序：`feishu_amarket_bot/listener.py`

当前协议：

```text
/A
/A 参数
```

当前行为仅包括：

- 通过飞书长连接接收消息。
- 去掉机器人提及标记。
- 识别统一的 `/A` 前缀。
- 把识别结果写入本地日志。

当前不包括：

- 把参数转换为行情查询。
- 调用本机 AI 查询入口。
- 向飞书发送回答。
- 用户权限、群范围、限流或审计规则。

因此，飞书部分目前不能被描述为已完成的行情问答接口。

## 6. 外部同花顺接口边界

`app/hithink/api.py` 封装了项目所需的外部读取能力，包括全 A 快照、交易日历、三类池、
板块指数和数据文件地址等。外部接口的具体地址、认证信息和供应方约束属于实现与本地配置，
不在本草案中公开。

调用外部接口必须遵守现有批量、时间和交易日检查，不应仅根据本文另写一套采集逻辑。

## 7. 后续接口扩展原则

- 默认只读；任何写入或任务控制能力必须拆分并单独授权。
- 本机查询入口继续绑定回环地址，除非用户明确批准新的网络范围和安全方案。
- 每个接口说明输入、输出、错误、超时、结果上限和是否改变数据。
- 飞书接入查询前，先确定允许的查询范围、身份识别、敏感字段处理和回复长度。
- 接口行为变化时同步更新本文、测试和调用方说明。
